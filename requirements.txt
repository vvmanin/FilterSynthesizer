# FilterSynthesizer runtime dependencies.

# Everything is bounded on purpose. The previous file was fully unpinned, so a
# fresh install picked up whatever was current that day while the dev machine
# kept an older resolution -- which is why the reported failures were not
# reproducible locally.
#
# numpy < 2.4 is the important one. NumPy 2.4 (numpy/numpy#29030) added a
# process-wide guard in numpy._core._multiarray_umath that raises
#   ImportError: cannot load module more than once per process
# if the extension is initialised twice in one process. mp_fix.py removes the
# code path that did that, so this cap can be lifted once a build has been
# smoke-tested against numpy >= 2.4 on Windows (both `streamlit run app.py` and
# the PyInstaller EXE). Raise it deliberately, not by deleting the bound.
