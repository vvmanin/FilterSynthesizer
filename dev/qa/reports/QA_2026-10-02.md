## 4. Issues found

Design ids spell the sidebar state: `RESPONSE_TYPE_order_frequencies_gain_…`
(`BW` Butterworth, `CH` Chebyshev, `IC` Inverse Chebyshev, `EL` Elliptic,
`BS` Bessel, `ED` Equiripple Delay; `n5` order 5, `a24` asymmetric LP 2 / HP 4;
`50-2500Hz` corners; `g2` passband gain 2; `a1` α = 1 dB; `s40` A_s = 40 dB;
`abs` = *Enable 3rd-Order Sections* on; `first` / `last` / `equalize` = gain
distribution). A job id adds the Topology variant and section:
`family-opamp-envelope[-atten][-alt]|S<n>|<cells>` (`atten` = Batch mode +
*Custom DC gain* 0.5 on every section; `typical` = TL072H, `slow` = AD8505,
`ideal`; envelopes in `dev/qa/matrix.py` `ENVELOPES`). The full design dict of
every id is in a run's `results.jsonl`.

### 4.1 Solver error: VCVS 3rd-order attenuated LP sections route to unregistered cells

- **Symptom:** Topology tab "Solver error", `KeyError: '3LP-atten'` (14 jobs) and
  `KeyError: '3LPn-atten'` (9 jobs) per standard run.
- **Reproduce:** `CH_LP_n3_1kHz_g10_a1_abs` (Chebyshev LP n = 3, 1 kHz, gain 10,
  α 1 dB, *Enable 3rd-Order Sections* on) → Topology, VCVS, section 1 (the 3rd-order
  section), tick *Custom DC gain* and enter 0.5 → Solve. Same for any 3rd-order
  LP / LPn section whose effective gain is < 0.98, e.g.
  `EL_LP_n7_sb_rolloff_100Hz_g1_a0.5_s40_abs` (with the pairing's own gain share),
  `IC_LP_n7_1kHz_g10_s80_abs_first` (3LPn).
- **Cause:** `topology_tab.py` ~L1915–1927 sets `mode = "atten"` for any gain < 0.98
  and builds `f"{order}{prefix}-{mode}"`; `cells_lp.all_cells()` (L51–67) creates the
  attenuator (R7) variant for **order 2 only**. HP is not affected (`3HP-atten`,
  `3HPn-atten` exist). `dev/fs028/fs028_common.route` copies the same naming.
- **Fix direction:** either route 3rd-order LP/LPn atten to an existing cell (e.g.
  unity cell + input divider) or gate it (`unsupported` / message as for BP1LP on
  VCVS) — or add the 3rd-order R7 cells (new cell → TF cache bump, schematic,
  `spice_cells` entry, LTspice template per CLAUDE.md).

### 4.2 App exception in band-pass auto-pairing

- **Symptom:** the app shows an exception on the Biquad Pairing tab:
  `ValueError: min() arg is an empty sequence`.
- **Reproduce:** `BW_BP_n1_50-2500Hz_g2_abs` — Butterworth, Bandpass, Order 1,
  Unit Hz, 50–2500 Hz, gain 2, Biquad Pairing: *Enable 3rd-Order Sections* on.
- **Cause:** `pairing_utils.auto_pair_bandpass` L155: the residual origin zero is
  dumped into `min(stages_pool, …)`, but with n = 1 and a wide band the prototype
  pole becomes two real poles, so there is no complex-pair stage (`stages_pool`
  empty) once absorption is on.
- **Pinned:** `matrix.PINNED` (every level).

### 4.5 Smaller observations

- **Cells never routed** in any run: `2BP-AM2` (possibly dead); rare in the
  standard sample: `2BP1LP-MFB(-QE)`, `2LPn-gained+R7`, `3LPn-gained+R7`,
  `3LP-unity`, `3LPn-unity` (the full level may reach them).
- **Reported stopband edge** = where the attenuation is A_s − 0.1 dB
  (`filter_solvers.find_crossing` margin) — the report's "Calculated stopband
  edge" is 0.1 dB short of A_s by construction.
- **Delay-preserving (translation) BP** keeps its −α corners only for b ≲ 0.3
  (FS-006 note §4.3); wider bands pass the app's fold check but the corners drift
  by several dB (e.g. `BS_BP_n2_delay_50-2500Hz_g2`: 24 dB at f1). No warning is
  shown for that range.
- **App-reported limit** ("Stopband Attenuation does not meet requirements") for
  narrow asymmetric Elliptic / Inverse-Chebyshev BP, e.g.
  `EL_BP_a42_10-15kHz_g10_a0.5_s30-80_abs` — the app says so itself.
- `verify.py` never exits non-zero (the harness reads its "realizer all-pass"
  line instead).
- Streamlit 1.64 deprecations on every run: `use_container_width` (removal
  announced after 2025-12-31) and `st.components.v1.html` → `st.iframe`.
- Streamlit log: `widget_gain` "created with a default value but also had its
  value set via the Session State API" (`ui_components.draw_gain_block`).

## 5. Expected, not issues

- 7 designs refused by the app on purpose: "Band too wide for the
  delay-preserving bandpass" (6, e.g. `ED_BP_n4_delay_d5_50-2500Hz_g1_abs_last`) and
  the Custom H(s) gate "Bandpass with 2 real poles … (FS-016)" (1).
- `NO_BOM_EXPECTED` (130) and `NO_BOM_ENVELOPE` (999): infeasible gain / structure,
  or a realization needing more R / C spread than the envelope allows — mostly the
  `narrow` envelope and the 95 kHz-GBW AD8505.
- `DEGRADED` (1 641): BOMs with best snap cost > 5 or a > 10 % ideal-case shape
  deviation; 2/3 of them with the AD8505 op-amp.
